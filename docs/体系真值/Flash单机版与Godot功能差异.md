# Flash 单机版与 Godot 功能差异

## 1. 对照范围与结论口径

- 盘点日期：2026-11-25。
- Godot 代码基线：提交 `1444473e09c3`。
- 功能参考：当前“嗯哼休闲服单机 3.0”Flash 单机包，以下简称“参考包”。它是本次补齐目标，不等同于未经修改的历史官方客户端。
- 参考包保留 Flash 客户端，附带 Python 服务端及网页扩展；本项目重写客户端，并使用另一份服务端快照。
- 本次检查界面入口、请求方法、回包分发、状态字段及参考包服务端处理，不以窗口数量、协议常量数量或测试通过数量计算“完成率”。
- 本次没有逐项运行双方玩法，也没有执行跨客户端、跨存档的迁移验证。参考包的入口开关、开放时间和奖励是否可用，仍需实机核对。

状态分为：

| 状态 | 含义 |
|---|---|
| 明确删减 | 当前代码明确说明移除了该功能；恢复属于范围变更，不应当作普通修 Bug |
| 部分接入 | 已有请求或界面，但有具体回包、状态、操作或展示环节缺失 |
| 未发现客户端接入 | 参考包有处理逻辑，本次在 Godot 入口及协议链路未找到对应完整实现；补齐前仍需实测确认 |
| 已有实现 | 当前代码已存在实际调用，不再沿用旧文档的“未实现”结论；不表示已通过本次端到端验收 |

**主要结论：差异不仅是 UI。缺口同时涉及完整玩法、协议适配、状态同步和表现层，不能只补窗口，也不能直接替换服务端。**

## 5. 服务端与协议兼容性阻断

### 5.1 已确认的协议号冲突

| 协议号 | 参考包 | 当前 Godot 客户端与配套服务端 |
|---|---|---|
| `7779` | `XIANREN_MODE`，仙人模式 | `AUTO_SELL_CONFIG`，自动出售配置 |

Godot 依据：[客户端定义](../../脚本/单例/后端连接.gd#L508)、[配套服务端定义](../../服务端/runtime/tools/fake_flash_server.py#L930)。
参考包依据：`tools/fake_flash_server.py` 的 `ClientOpcode.XIANREN_MODE` 与 `handle_xianren_mode()`。

**后果：直接将 Godot 客户端连接参考包服务端，自动出售请求可能按仙人模式请求解释。**
两边当前各用自己的配套服务端，不应据此宣称本项目现有自动出售必然出错；风险发生在混用或迁移时。

### 5.2 除协议号外还需对齐的内容

1. 请求参数形状、子命令编号、返回字段顺序和数据类型。
2. AMF3 文本/JSON 桥与 Flash 原始二进制回包的转换覆盖。
3. 角色资料、装备、技能配置、活动与战场状态的数据契约。
4. 每条成功、拒绝、失败回包的 UI 消费者，以及更新后是否允许重试。
5. 存档结构与迁移策略；本次没有验证账号、角色或存档可以互换。

因此不得用“复制服务端目录”代替移植方案，也不能只比较协议常量交集。

## 8. 建议补齐顺序与验收标准

| 优先级 | 范围 | 进入下一阶段前的最低验收 |
|---|---|---|
| P0 | 协议、字段和存档契约 | 消除 `7779` 等冲突；明确选用哪套服务端；关键请求、成功与拒绝回包都有可重放样本；不覆盖日常存档 |
| P1 | 单人核心闭环 | 按确认范围恢复装备成长，补仙人、百炼、通天塔和死亡复活；实际完成“入口→请求→结算→状态刷新→重登保留” |
| P2 | 社交、经济与任务 | 补师徒、羁绊、拍卖、悬赏、收藏及护送状态；用双账号验证双方状态和资源变化 |
| P3 | 战场族 | 逐项完成报名、匹配、进出场、阵营规则、计时、胜负及领奖，不能以频道窗可打开作为完成依据 |
| P4 | 表现与参考包扩展 | 补详情、通告、气泡、外观层与抽奖扩展；先确认哪些有意删减要恢复，哪些保持 Godot 自身设计 |

以上是建议顺序，不代表已经批准恢复所有历史删减。后续实施应按功能编号拆分任务，并记录双方入口、操作、预期、实际结果及未验证项。
